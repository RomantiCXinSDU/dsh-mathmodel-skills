# Requirement 编号规则（problem_spec 专用）

## 编号格式
- `R<小问号>.<序号>`：R1.1、R1.2、R2.1、R2.2 …
- 附件/数据类要求若跨小问，用 R0.n（如 R0.1 = "附件1 提供了 X 字段"）
- 只增不改：后续发现遗漏用下一段空号补（R1.3），**禁止重编已发布的编号**——下游 candidate、model_review、decision_log 都用 `[[problem_spec#Rn.n]]` 引用，重编即断链

## 双向覆盖（可追溯）
- 正向：题目正文+附件说明逐句过，每句要么归入某 R，要么标"背景信息"
- 反向：每个 R 标注原文出处（页码/段落）
- 验收脚本会检查：正文出现的 R 必须都在"要求编号清单"中有定义

## 每个 R 的最小信息
```markdown
- R1.1：<一句话要求>（原文出处：第_页第_段；输入：___；输出：___；成功判据：___）
```
成功判据写不出的 R → 进"需人工裁决项"，禁止脑补。

## 与小问依赖的关系
- R 描述"做什么"，不描述"怎么做"；任何"用 XX 方法"字样出现在 R 里都是越权
- 小问依赖只写结果接口（Q2 依赖 Q1 的哪个输出），并给证据（题面/数学接口/业务机制）
